# AdamLife 2.0 · Obsidian Graphite

React, TypeScript и Vite: финансовое ядро, серверная авторизация и отдельная демонстрация.
Старые SwiftUI и Flutter проекты не используются и не изменяются.

## Финансы — 2026-11-05

После входа `src/finance/Workspace.tsx` получает реальные данные из `/api/finance`.
`client.ts` — API и точная денежная арифметика BigInt; `Editors.tsx` — счета, категории,
доходы/расходы/переводы. Используются существующие Layout, Modal и Graphite-токены.
Счета и операции не создаются автоматически. Демо остаётся отдельным `App`.
Управление счетами и категориями доступно кнопками над сводкой; валюты выбираются отдельно.
На backend нужна миграция `0004_finance`. Местная БД уже обновлена, облачная — ещё нет.
27 точечных frontend-тестов и production build прошли; проверка нового UI на iPhone
выполняется после согласованного деплоя.

Следующим локальным этапом добавлены параметры депозитов: накопительный/срочный,
годовая ставка и отдельные даты открытия/окончания. Поля находятся в прежней форме счёта;
карточка открывает детали с переходом в историю и редактирование. На узком экране поля
идут в одну колонку. Нужна миграция API `0005_deposit`; этот этап ещё не опубликован.
Точечные frontend-проверки: 22 passed, TypeScript и Vite build успешны.

## Авторизация — текущий этап

Сначала запустите adam_life_api/start-api.cmd, затем start-adamlife.cmd.
Откройте **http://localhost:5173/** (этот origin используется для Google callback).
Настройка Google: adam_life_api/configure-google.cmd; инструкция и HTTPS-размещение —
[authentication.md](../adam_life_api/docs/authentication.md).

Экран входа использует Graphite. Сессии — HttpOnly cookies backend, профиль/CSRF только
в памяти. Приватные страницы скрываются без сессии; выход очищает память.
Google-кнопка отключена, если backend сообщает об отсутствии credentials.
«Посмотреть демонстрацию» явно открывает прежний прототип; он не является данными
аккаунта. Авторизованный аккаунт пока пустой: финансовый CRUD сервера — будущий этап.
Старое localStorage не переносится в PostgreSQL и не удаляется.

src/auth/: transport, controller, AuthRoot, стили и тесты. Vite /api proxy ведёт
на localhost:8000; публичный frontend использует аналогичный HTTPS proxy (шаблон:
deployment/vercel.example.json). Ниже — описание сохранённого демо-режима.

## Как открыть

На компьютере откройте `start-adamlife.cmd` двойным нажатием; оставьте окно открытым. Если сервер уже работает: http://localhost:5173/.

Для просмотра с iPhone запустите **start-adamlife-iphone.cmd**. Компьютер и телефон должны быть в одной доверенной Wi-Fi сети. В Safari откройте адрес **Network**, который показывает окно запуска. Во время проверки это был http://192.168.0.184:5174/. IP может измениться. Компьютер должен оставаться включённым; из внешней сети ссылка не работает. Если Windows блокирует доступ, владельцу потребуется разрешить Node.js для своей частной сети. Программа не меняет правила брандмауэра сама.

Для запуска из терминала, если зависимости уже установлены:

```sh
npm run dev
# Или просмотр в локальной Wi-Fi сети:
npm run dev -- --host 0.0.0.0 --port 5174
```

`index.html` не открывается с диска напрямую. Это локальный запуск, не обновление старого Vercel-сайта. При первой подготовке проекта нужны совместимый Node.js (22.12+ / современная LTS) и `npm ci`.

## Что изменено

- **Главная:** независимый от аналитических фильтров общий баланс, доходы/расходы текущего месяца, Kaspi/Freedom/наличные, ближайшие платежи, четыре последних операции, быстрые действия. Больших графиков нет.
- **Операции:** совместимые фильтры периода, счёта, типа, категории и поиска; сортировка даты/суммы; сводка результата; группировка по дате при сортировке дат. При сортировке суммы дата остаётся в каждой строке. Импорт доступен отдельной кнопкой, не вкладкой.
- **Аналитика:** доходы/расходы/разница периода, интерактивные месяцы, выбор сектора/категории, переход с сохранением периода и счёта, дневная/накопительная динамика и доступный с клавиатуры ползунок даты, средние расходы и ведущая категория. Категорийная сумма и доля относятся к выбранному периоду; сравнение явно подписано и всегда сопоставляет выбранный месяц с предыдущим месяцем.
- **Платежи:** добавление, редактирование, детали, отметка оплаты, отдельные статусы; разовые и ежемесячные обязательства. 31 число переносится на последний день короткого месяца, затем возвращается на 31. Оплата каждого месяца хранится отдельно. Отметка оплаты не создаёт финансовую транзакцию и не меняет остатки счетов. Можно вручную связать её с существующим расходом данного счёта и месяца. Полноценной автоматической сверки пока нет.
- **Формы:** расходы, доходы и собственные переводы, отдельные счета, строгая проверка сумм/дат. При редактировании тиыны не округляются. Для переводов счета должны отличаться.
- **Импорт:** загрузка → проверка → результат. Файл выбирается, но его байты не читаются. Состояние подготовки явно относится к готовому примеру. Работают смена категории, исключение/возврат, просмотр совпавшей записи, подтверждение спорной строки. Счётчики вычисляются из выбора, повторная запись блокируется по стабильному ID примера, а не по дате/сумме. Непроверенные строки не добавляются; пока окно открыто, к ним можно вернуться. Незавершённая проверка после закрытия окна не сохраняется.

Нижняя/боковая навигация: Главная, Операции, Аналитика, Платежи. На телефоне кнопка `+` вынесена в отдельную нижнюю область, не перекрывающую прокручиваемые строки. Есть safe-area, управляемая высота диалогов при изменении visual viewport и sticky-действия. Тема Graphite закреплена; временного переключателя и футеров нет. В шапке оставлено одно обозначение «Тестовые данные» с пояснением.

## Данные и ограничения

Ключ localStorage не изменился: `adamlife.web.prototype.v1`. Старые операции, суммы, даты и ID сохраняются. Схема расширена добавлением счетов и платежей; начальный остаток распределяется по счетам без изменения общего итога. Уже назначенные счета не переназначаются. Старое Flutter-хранилище не читается и не меняется.

Суммы — целые тиыны. Общий баланс — сумма остатков всех счетов, включая начальные остатки. Собственные переводы меняют только два счёта, не доходы и расходы. В аналитике используется единая с операциями функция фильтрации. Среднее за текущий период учитывает прошедшие календарные дни, за завершённый — полную длительность. При нулевой базе сравнение не превращается в бесконечный процент.

Запись выполняется только в браузер; сбой/запрет localStorage явно сообщается. Reload сохраняет подтверждённые изменения. Но это **не единственное надёжное хранилище реальных финансов**: очистка данных сайта, приватный режим и ограничения браузера могут удалить записи. Разные адреса (`localhost`, `127.0.0.1`, LAN IP, HTTPS-домен), порты, устройства и браузеры имеют разные хранилища. Синхронизации нет. Исходный повреждённый JSON не удаляется при загрузке автоматически.

Для авторизации подключён отдельный FastAPI/PostgreSQL backend. В демо-режиме нет
банковских подключений, настоящего PDF-парсинга, автоматического определения банка,
ИИ, правил категоризации, push и Telegram. Все исходные финансовые суммы и
импортируемые примеры вымышлены.

## PWA

Подготовлены `manifest.webmanifest`, имя AdamLife, standalone, scope/start URL, PNG 192/512, maskable-безопасный знак, Apple touch icon 180, iOS meta и viewport-fit=cover. Иконки уже включены в проект; `scripts/generate-icons.ps1` лишь воспроизводит существующий монограммный знак средствами Windows и не нужен для сборки на Mac.

**Нет service worker и гарантированной offline-работы.** API-ответы не кэшируются. Manifest/meta — подготовка, а не подтверждение установки на физический iPhone. LAN HTTP нужен для просмотра UI; полноценную установку проверять отдельно на HTTPS-размещении frontend. Будущий backend для этого не требуется, но в этом этапе размещение не выполнялось.

После HTTPS-публикации: Safari → Поделиться → На экран «Домой» → при наличии включить «Открывать как веб-приложение» → Добавить. Затем открыть именно иконку с домашнего экрана и проверить отсутствие адресной строки, safe-area, клавиатуру и повторный запуск. Официальные справки: [Apple](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios), [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Локальное упрощение финансового интерфейса — 2026-11-10

Сводка использует прежние серверные балансы: доступные средства, накопления и всего средств. `AccountGroups`, `OperationRows` и `DepositDetails` объединяют отображение счетов, цветовую семантику операций и внутренние вкладки депозита (Обзор / Накопления / История).

Цели, распределения, планы пополнений и прогноз скрыты из интерфейса; их модели, API, данные и расчёты сохранены. Пополнение и снятие открывают существующую форму перевода. Скрытая ставка не передаётся при редактировании; начальный баланс и дата учёта изменяются только явно, с прежним подтверждением. Миграции не требуются.

## Аналитика авторизованного пользователя — 2026-11-11, только локально

`src/finance/FinancialAnalytics.tsx` использует единственный существующий `/finance/snapshot`: операции, категории и текущие остатки. Расчёты вынесены в `analytics.ts`, стили — в `analytics.css`. Демо-прототип остаётся отдельным. Backend, OAuth, RLS, схема БД и предыдущие изменения депозитов не изменены.

- Периоды: текущий/прошлый месяц, 3/6/12 календарных месяцев и пользовательские даты. Последние N месяцев начинаются с первого дня месяца N−1 месяцев назад и заканчиваются `as_of` из API (дата пользователя). Сравнение с предыдущим календарным блоком; для неполного текущего месяца — соответствующие дни, с ограничением последним днём короткого месяца. Произвольный диапазон сравнивается с непосредственно предшествующим диапазоном того же количества дней. Даты вычисляются в UTC как календарные даты без локального смещения.
- Выбор одного/нескольких счетов и валюты. Категории представлены полосами или интерактивным SVG-кольцом; переключение не сбрасывает фильтры. Переход к операциям сохраняет даты, валюту, счета, тип и категорию, включая отсутствующую категорию. В общей истории добавлены только необходимые параметры фильтрации.
- Все суммы считаются в BigInt, в Number переводятся только пропорции графиков. Переводы исключены по типу независимо от выбора счёта. Начальные остатки и прогнозные проценты не считаются доходами. Записанные доходы на депозит учитываются как доходы. Изменения операций отражаются после штатного обновления snapshot.
- Нижний блок депозитов использует актуальные остатки отдельно для KZT/USD/EUR, включая архивные депозиты. При выборе счетов показывает только выбранные депозиты. Период операций не ограничивает текущие остатки.

Проверки: `vitest run src/finance/analytics.test.tsx` — 32 passed; `src/finance/finance.test.ts` — 12 passed. Всего 44, без пропусков. Проверены календарные границы, точность, фильтры, переводы, неизвестные категории, изменение/удаление операций, источник операций, интервалы графика, сравнения и рендер изменённых компонентов. `tsc -b --pretty false` и `vite build` выполнены по одному разу, успешно. Полный набор тестов не запускался. Новая браузерная проверка и физический iPhone не выполнялись из-за известного ограничения локального входа; мобильная компоновка подготовлена в CSS, требует визуальной приёмки.

Импорт и дедупликация не реализованы: аналитика читает сохранённые операции независимо от способа создания, будущий импорт должен обеспечивать их уникальность до сохранения. Для большой истории агрегацию позже можно перенести на сервер; сейчас используется полный существующий snapshot. Новых зависимостей и миграций нет. Публикация не выполнялась.

## Kaspi Gold — 2026-11-13, локально

`src/finance/KaspiImport.tsx` открывается кнопкой «Импорт выписки» в финансовом интерфейсе. Загрузка, предпросмотр/сверка, подтверждение, история/отмена и пользовательские правила находятся в существующем модальном окне. Новая основная вкладка не создаётся. Требуется backend со схемой 0007_kaspi. Корректировки показываются отдельным видом в истории и меняют фактические остатки. Подтверждённые возвраты/отмены расхода уменьшают расходы исходной категории в дату возврата. FX и неподтверждённые корректировки не включаются в доходы/расходы; общий источник операций остаётся прежним. Неоднозначные строки требуют решения, никакого автоматического импорта без подтверждения. Исходный PDF и секреты в браузерном хранилище не сохраняются. Полные решения и проверки: ../adam_life_api/docs/decisions.md и verification.md. Публикация не выполнялась.
